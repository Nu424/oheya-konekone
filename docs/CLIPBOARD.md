# コピー＆ペースト（設計メモ）

> 実験自動化装置のレイアウト版（tsubame-layout-designer）で設計・実装し、このリポジトリへ持ち込んだ仕組み。
> 文中の例（架台・プレート・ラック・ロボット）は装置版のまま残してある。部屋版では「デスク → モニター」「本棚の段 → 小物」と読み替えてほしい。
> この部屋版での扱いは「4. この部屋版での扱い」の節にまとめた。

選んだアイテムを `Ctrl+C` / `Ctrl+X` / `Ctrl+V` でコピー・切り取り・貼り付けする仕組み。

実装は 3 か所。

| ファイル | 役割 |
|---|---|
| [src/editor/clipboard.ts](../src/editor/clipboard.ts) | クリップボードの形式、読み書き、貼り付けるアイテムの生成。状態を持たない関数だけ |
| [src/editor/commands.ts](../src/editor/commands.ts) の `copySelection` / `cutSelection` / `pasteText` | 選択・ストア・通知とつなぐ。貼り付け位置を決める |
| [src/ui/Chrome.tsx](../src/ui/Chrome.tsx) の `useShortcuts` | ブラウザの `copy` / `cut` / `paste` イベントを受ける |

## 1. 方針

1. **OS のクリップボードに、JSON の文字列として入れる。** アプリ内の変数には持たない。
2. **載っているものも一緒に運ぶ。** 架台をコピーすれば、プレートもラックもロボットもついてくる（積み重ねの仕組みは [STACKING.md](STACKING.md)）。
3. **位置は「コピーしたアイテムからの相対」で持つ。** どこに貼っても、中の並びがそのまま再現される。
4. **貼り付け先はマウスの下。** ビューの上にマウスがあれば、その下の面（天板・棚・床）に置く。なければ元の位置の隣に置く。
5. **ふつうの文字のコピペを邪魔しない。**

### なぜ OS のクリップボードか

アプリ内の変数に持つ案（実装は数行で済む）も検討した。採らなかった理由は次のとおり。

- **別のタブ、別のレイアウトへ持っていける。** レイアウト A で組んだモジュールを、レイアウト B に貼れる。アプリ内の変数ではタブをまたげない。
- **テキストとして扱える。** エディタに貼って保存する、チャットで人や AI に渡す、少し書き換えてから貼る、ができる。レイアウト JSON と同じ「人も AI も同じ形式で扱える」という方針に合う。
- **再読み込みしても残る。**
- 引き換えに、貼り付け時に中身を検証する必要がある（外から来た文字列なので）。検証はレイアウト JSON の読み込みと同じものを使う。

### なぜ `copy` / `paste` イベントか

キーの押下（`keydown` の `Ctrl+C`）で `navigator.clipboard` を呼ぶ案もある。採らなかった理由は次のとおり。

- **読み取りの許可ダイアログが出ない。** `navigator.clipboard.readText()` はブラウザが許可を求める。`paste` イベントの `clipboardData` は、ユーザーの操作そのものなので許可が要らない。
- **OS やブラウザのメニューからの操作も拾える。** 右クリックメニューや「編集」メニューのコピー・貼り付け、Mac の `Cmd+C` も同じイベントになる。
- **文字のコピペとの切り分けが 1 か所で済む。** イベントの中で「いまは文字を扱っているか」を見て、そうなら何もしない（ブラウザの標準動作に任せる）。

## 2. クリップボードの形式

```jsonc
{
  "kind": "layout-items",        // この形式の目印
  "version": 1,
  "origin": { "position": [2100, 850, 1500], "rotation": 0 },   // コピー元（先頭のアイテム）の位置と向き
  "items": [
    // 先頭がコピーしたアイテム（ルート）。offset は [0,0,0]、turn は 0
    { "type": "deckPlate", "params": { "width": 600, "depth": 500 }, "offset": [0, 0, 0], "turn": 0 },
    // 以降は載っていたもの。offset はルートからの相対位置、turn はルートからの相対回転
    { "type": "riser", "params": { "height": 100 }, "offset": [170, 26, -120], "turn": 0 },
    { "type": "mg400", "params": { "j2": 30 }, "offset": [170, 126, -120], "turn": 270 }
  ]
}
```

- **`id` は入れない。** 貼り付けるたびに新しい id を振る。
- **`offset` はルートの向きを打ち消した座標**で持つ（ルートが 90° を向いていても、中身は「ルートが 0° のとき」の並びで記録する）。貼り付け時に、貼り付け先の向きで回し直す。こうしておくと、コピー元がどちらを向いていたかに左右されない。
- **`origin`** は「元の位置の隣に貼る」ときにだけ使う。
- `locked` は運ばない（貼り付けたものは動かせる状態にする）。

## 3. 動き

### コピー（`Ctrl+C`）

1. 選択中のアイテムをルートにする。何も選んでいなければ何もしない（複数選択のときは 5 章）。
2. `stack.riders()` で、ルートに載っているもの（孫・ひ孫まで）を集める。
3. `makeClip()` で上の形式にして、`clipboardData.setData('text/plain', …)` に入れる。
4. 「載っているもの 3 点と一緒にコピーしました」と知らせる。

### 切り取り（`Ctrl+X`）

コピーしたあと、ルートと載っているものをまとめて消す。
削除（`Delete`）は「上の物は下の面に落ちる」が、切り取りは「一式を持っていく」。貼り付けで同じ一式が出てくるので、こちらのほうが自然。

### 貼り付け（`Ctrl+V`）

1. `parseClip()` で読む。
   - JSON でない、または `kind` が違う → この形式ではない。何もしない（レイアウト全体の JSON なら、読み込みとして扱う）。
   - この形式だが、未知の種類や範囲外のパラメータがある → 「貼り付けできませんでした: items[1].params.tip: …」と場所つきで知らせる。
2. 貼り付け位置を決める。
   - **マウスがビューの上にある**：マウスの視線が最初に通る面（`pickAlongRay`、ドラッグと同じ処理）にルートを置く。フロアからはみ出すなら内側に寄せる。
   - **それ以外**（パネルの上にいる、など）：元の位置から、ルートの幅＋すき間だけ右へずらす。高さは、その場所の真下の面に合わせる。
   - 壁付け・天井付けのアイテムは、元の高さのまま隣に置く。
3. 同じものを同じ場所に続けて貼ったら、20 mm ずつずらす（重なって 1 個に見えるのを防ぐ）。
4. `instantiateClip()` で新しい id のアイテムを作り、まとめて追加する（undo 1 回分）。ルートを選択した状態にする。

### 文字のコピペと切り分ける条件

次のどれかに当てはまるときは、イベントに手を出さない。

- フォーカスが `input` / `textarea` / `contenteditable` にある
- ページ上で文字が選択されている（`window.getSelection()` が空でない）
- ダイアログが開いている

## 4. この部屋版での扱い

- 実装は装置版と同じ（`src/editor/clipboard.ts`、`commands.ts` の `copySelection` / `cutSelection` / `pasteText`、`Chrome.tsx` の `useShortcuts`）。
- 壁付けのアイテム（エアコン・カーテン）は、貼り付けたあと `flushToWall` でいちばん近い壁に付け直す。
- 通知文は部屋版の口調（「コピーしたよ」）にそろえた。
- テストは `src/__tests__/clipboard.test.ts`（在宅ワークのテンプレートのデスク＋モニター＋デスクライトで確かめている）。

## 5. 複数選択のとき

複数選択（[MULTISELECT.md](MULTISELECT.md)）でも、形式はそのまま使える。

- `items` の先頭は「主」（最後に選んだもの。それが別の選択に載っているなら、最初の根）。
- 続いて、ほかの「選んだもののうち、別の選択に載っていないもの」、そのあとに載っていたもの。どれも、先頭からの相対位置と相対回転で持つ。
- 貼り付けると、先頭がマウスの下の面に載り、ほかは並びを保って置かれ、それぞれ真下の面に着地する。
- どれが「選んだもの」でどれが「載っていたもの」かは、形式には書かない。貼り付けたあとの位置関係から求める（載っているものは、載せているものと一緒に貼られるので、関係がそのまま再現される）。

## 6. いまの割り切り

- **貼り付け先での重なりは避けない。** マウスの下にそのまま置く。重なれば、ふだんどおり赤枠で知らせる。
- **スマホなど、キーボードのない環境**では使えない（複製ボタンは使える）。
- **形式の `version` が上がったとき**の読み替えは、まだ用意していない（いまは 1 だけ）。
