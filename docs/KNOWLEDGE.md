# 開発で得た知見

実装しながらわかったこと、試してだめだったこと、ハマった罠のまとめ。
コードを読めばわかることより、「なぜそうしたか」「次に同じことをするときの近道」を残す。

## 1. パラメトリックな3Dモデルの作り方

### 基本の考え方
- **プリミティブの組み合わせで十分きれいになる**。箱・角丸箱・円柱・回転体（lathe）・押し出し（extrude）・チューブ・ロフトの7種類で、33種類の家具をまかなえた。外部の glTF に頼らないので、色もサイズも自由に変えられて、ファイルも軽い。
- **mm で組んで、ルートを 0.001 倍する**。家具の寸法は mm で考えるのが自然。ただしシーンを mm にすると、点光源の減衰や影のバイアスが物理的におかしくなる。なのでシーンは m にして、アセットのルートだけ縮める。
- **原点は底面中心、正面は +Z** に統一する。回転・壁への吸い付き・サムネイルのカメラ位置・当たり判定が、全部この前提で単純になる。
- **寸法は組み立てたモデルの外接箱（bounding box）から測る**（`itemFootprint`）。パラメータの width/depth から計算すると、ヘッドボードやひじ掛けの分がずれる。ギャラリー・当たり判定・AI向けの寸法表は、すべてこの外接箱を使っている。

### 質感を上げるコツ
- **UV を実寸（1リピート = 1m）で書く**（`kit.ts` の `box`）。BoxGeometry の UV は面ごとに 0〜1 なので、そのままだと大きな板ほど木目が間延びする。面ごとにサイズを掛けて、木目の向き（grain）も面ごとに決める。
- **木目は「ほぼ平行な線」**。最初に作った sin ベースの年輪は、波打った縞模様になって作り物っぽかった。U方向に引き延ばしたノイズを重ねて、線の間隔をノイズで揺らし、細い濃い線（晩材）を足すと自然に見える。
- **布は `MeshPhysicalMaterial` の sheen**。織り目のテクスチャを map と bumpMap の両方に使うと、ソファやクッションが一気に布らしくなる。
- **ロフト（輪郭を積み重ねたメッシュ）は布の垂れ下がりに強い**。こたつ布団は、角丸の四角を高さごとに広げて重ねる（下に行くほど指数的に広がる＋すそを波打たせる）だけで、それらしくなった。角丸箱を重ねた最初の版は、ぼてっとしたクッションにしか見えなかった。
- **細かい「生活感」が効く**。本棚の本（乱数の種を固定して並べる）、ハンガーラックの服、冷蔵庫のマグネット、テレビ台のゲーム機。少し入れるだけで部屋が急にそれらしくなる。乱数は必ず種を固定して、毎回同じ見た目にする（スクショ比較のため）。
- **植物は葉の形が9割**。ShapeGeometry で葉の輪郭（ハート型・剣型・モンステラの切れ込みは穴）を作り、主脈で折って先を垂らすだけでかわいくなる。

### パラメータ設計
- **パラメータは1回だけ定義して、そこから全部作る**（`params.ts` の DSL）。zod の検証・UI のスライダーやスウォッチ・AI 向けの説明文が、全部ひとつの定義から出る。項目を足すときは定義に1行足すだけで済む。
- **範囲は極端な値でも破綻しないように決める**。ギャラリーの「最小」「最大」を必ず目で見る。脚の長さが 0 になる、ひじ掛けが幅を超える、といった破綻は、ここでほぼ見つかる。
- **select（形の切り替え）は見た目の差が大きい**。ベッドのフレーム5種類のように、構造ごと分岐させるとバリエーションが一気に増える。

## 2. 部屋の描画

### 「ドールハウス」表示
- 外から見るとき、カメラ側の壁は腰より低い「スタブ」に差し替えて、中が見えるようにしている。判定はフレームごとに、壁の内側の面とカメラの位置関係を見るだけ。
- **消した壁や天井も影は落とさせる**。`colorWrite: false, depthWrite: false` のマテリアルに差し替えると、見えないけど影の計算には残る。これがないと、天井がないぶん真上から日が差して、部屋が真っ白になる。
- 壁の上の切り口は、濃い色（ポシェ）にすると図面っぽくなってかわいい。

### ライティング
- **トーンマッピングは AgX**。ACES より彩度の飽和が穏やかで、木や布の色が濁らない。
- **環境光を弱めにして、窓からの光を主役にする**。最初は環境光・半球光・天井の点光源を全部強めにしていて、のっぺりした絵になっていた。半分以下に絞ったら、陰影が出た。
- **窓ごとに RectAreaLight を置く**と、窓際が明るく奥が暗いグラデーションが自然に出る（影は落ちないので、影は太陽の DirectionalLight が担当）。
- **窓の外は「空の板」**。窓の外側に、空と遠くのビルを描いた発光板（MeshBasic）を置いている。中から見たときに窓が明るく見えるだけで、室内らしさがぐっと上がる。時間帯に合わせて色を変える。
- **影は PCFShadowMap + radius**。three.js r18x では `PCFSoftShadowMap` が廃止されて、警告とともに PCF に置き換わる。
- **接地感には「偽物の接地影」が効く**。日なた以外では本物の影がほぼ落ちないので、家具の足元に、ぼかした角丸の黒い板を敷いている。高い家具ほど薄くする。N8AO（AO）と組み合わせると、浮いて見えなくなる。

### ポストエフェクト
- 構成は N8AO → AgX トーンマッピング → 弱いビネット → SMAA。`multisampling={0}` にして、アンチエイリアスは SMAA に任せる。
- AO が効いているかは `?ao=1` で確認できる（N8AO の renderMode）。

### 2Dの平面図
- 真上からの視点は、**本物の正投影カメラ**にする。遠くの透視カメラで代用すると、壁の内側の面が引き伸ばされて見える。
- 正投影の視錐台をピクセル単位にすると、`zoom` が「1m あたり何ピクセル」になって、画面に収める計算が簡単になる。
- **カメラの切り替えは、カメラを自前で2つ持つ**。drei の `<OrthographicCamera makeDefault>` を条件で出し入れすると、CameraControls が古いカメラにつながったままになった。両方のカメラを `useMemo` で作り、`set({ camera })` で切り替えて、CameraControls には `camera` を明示的に渡し、`key` を変えて作り直している。

### オーバーレイ
- **床の上に半透明の色を重ねると、日なたで色が飛ぶ**。床が HDR（1.0 を超える明るさ）なので、37% の緑を混ぜても白っぽくなる。動線チェックの塗りは `MultiplyBlending`（乗算）にして解決した。白なら変化なし、緑なら床が緑みを帯びる。
- DataTexture の行の向き（v 軸）は、回転した板と合わせるのを間違えやすい。texture の `repeat` / `offset` で反転するより、データを作るときに行を逆順に詰めるほうが確実だった。

### パフォーマンス
- `frameloop="demand"` で、止まっているときは描画しない。CameraControls・React のプロパティ変更・`invalidate()` で描画が走る。アニメーションやキー入力での移動は、`useFrame` の中で自分で `invalidate()` し続ける。
- 起動直後は影と AO を落ち着かせるために、数フレーム分 `invalidate()` している（`FrameProbe`）。

## 3. 撮影モード（パストレーシング）

- ライブラリは `three-gpu-pathtracer` の `WebGLPathTracer`（WebGPU 版を勧める非推奨警告が出るけど動く）。
- **最大の罠：マテリアル配列を持つメッシュがあると、以降のマテリアルが全部ずれる。** ライブラリは全メッシュを1つに結合するとき、グループを「メッシュ i 番目 → マテリアル i 番目」で振る。ところがマテリアルの一覧は、配列を持つメッシュのぶんを展開して数える。壁の上面だけ色を変えるために6面のマテリアル配列を使っていたら、床にモニター画面の画像が貼られ、ベッドが真っ黒になった。上面を別メッシュに分けて解決した。
  - 切り分けの手順：最小シーン（板2枚）→ 実際の部屋 → 家具だけ・部屋だけ、と半分ずつにしていった。家具だけなら正しく、部屋だけで壊れたので、部屋の作り方に原因があるとわかった。
- リアルタイム用の工夫は、撮影中は外す。
  - 環境光（PMREM）は使えないので、`GradientEquirectTexture` に差し替える
  - カットした壁（ゴースト）と偽物の接地影は、`visible = false` にする
  - 外から見下ろす構図では天井がないぶん日差しが強すぎるので、太陽を 35% に弱める
- 撮影中は `frameloop` を `always` にして、ポストエフェクト（EffectComposer）は外す。トーンマッピングはレンダラー側の AgX に切り替える。
- ソフトウェア描画（SwiftShader）だと、1分で数サンプルしか進まない。色や質感の確認には、10〜20サンプルあれば足りる。

## 4. 編集・配置のロジック

- **当たり判定は上から見た2D**。回転した家具の外形（四角形）どうしを分離軸定理（SAT）で調べて、高さの範囲も重なっているときだけ「重なり」にする。
- **「ぶつからない物」を決めておくのが大事**。最初は机の下の椅子、カーテン、座布団まで赤くなって、警告だらけになった。ラグ・カーテン・クッション・天井照明はぶつからない扱いにして、椅子は机やテーブルの下に入れてよいことにした。モニターが机に載っているような「上に載っている」関係も除外する。
- **吸い付き**：家具の外形の端を、壁・柱・近くの家具の端に、80mm 以内なら合わせる。どこにも合わないときは 50mm のグリッドに合わせる。壁掛けのもの（エアコン・カーテン）は、一番近い壁に背中を向けて張り付く。
- **新しく置く場所**：部屋の中心からぐるぐる外へ探して、重ならない場所を見つける。正面向きで見つからなければ 90° 回した向きでも試す。それでもなければ真ん中に置いて「空きがなかったよ」と伝える。
- **ドラッグ中にカメラを動かさない**。詳細パネルが開くのに合わせて画面をずらしていたら、ドラッグ中に部屋ごと動いて使いにくかった。
- **ドラッグは undo 1回分にまとめる**。開始時の状態を覚えて履歴を止め、終わったら一度その状態に戻してから、最終状態をまとめて記録する。

## 5. 動線チェック

- 床を 50mm のマス目にして、家具からの距離（距離変換）を計算する。ドアから塗りつぶしをして、体の中心が置けるマスをたどる。
- **基準**：ゆったり＝通路幅 60cm 以上、横歩きならぎりぎり＝40cm 以上。最初は 45cm にしていて、6畳の家具付きテンプレートが半分「たどり着けない」になった。マス目の誤差もあるので、判定は少しゆるめ（半径 190mm）にしている。
- **塗るのは「人が立てる範囲がカバーする床」**。体の中心が置ける場所だけを塗ると、壁際がいつも「通れない」と赤くなる。
- **椅子は障害物にしない**（引けば動かせる）。障害物にすると、椅子の奥のデスクが「たどり着けない」と誤判定される。

## 6. AI 連携

- ルール・カタログ・寸法表・いまの部屋をまとめてプロンプトにする。AI の返事はそのまま貼り付けられる（```json の囲みや前後の文章は自動で取り除く）。
- **エラーは「場所＋理由」で返す**（例：`items[0].params.width: 小さすぎる値…`）。zod の日本語ロケールを使っている。エラー文を AI に送り返す文面も、ワンクリックでコピーできる。
- **テンプレートのテストが、そのまま AI の出力の安全網になる**。実際に Claude がガイドだけを見て「在宅ワーク7畳」を設計したら、座椅子とベッドの重なり、植物が通路をふさぐ問題が出た。テストが両方とも見つけてくれた。

## 7. 検証のやり方

- `scripts/shot.mjs` で、インストール済みの Chromium（SwiftShader の WebGL）からスクショを撮る。`key:`・`click:`・`mouse:`・`drag:`・`wait:` の操作をつなげられる。`HOLD=1` を付けると、ドラッグ中のまま撮れる。
- **待ち時間は長めに**。ソフトウェア描画は1フレームが重く、クリックしてから画面が変わるまで数秒かかることがある。3〜6秒待つ。並列で撮ると遅くなって、ready フラグが間に合わない。
- ギャラリーは `/?gallery`（全部）、`&type=<type>`（1種類のバリエーション）、`&types=a,b,c`（数種類だけ）、`&only=<番号>`（1件を大きく）。ラベルは HTML ではなく3D内のテキストにしている（HTML ラベルは StrictMode で消えることがあった）。
- **ブラウザなしで寸法や動線を測れる**。`npx tsx` で、`analyzeFlow` や `itemFootprint2D` を直接呼べる（テクスチャは `HEADLESS` のとき空になる）。配置の数値を詰めるときに便利。
- dev サーバーは、バックグラウンドの時間制限（30分〜2時間）で止まることがある。スクショ前に `curl localhost:5173` で生きているか確かめる。
