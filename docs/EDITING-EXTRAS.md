# 編集まわりの 3 つの追加（設計メモ）

使ってみて足りなかった 3 つの編集機能の設計。

> 実験自動化装置のレイアウト版（tsubame-layout-designer）で設計・実装し、このリポジトリへ持ち込んだもの。文中の例（架台・ラック・AMR）は装置版のまま。
> この部屋版で変えたところは「この部屋版での扱い」の節にまとめた（とくに、数値の受け付ける範囲は装置版と違う）。

1. **上のものもまとめて削除**：削除するとき、載っているものを残すか一緒に消すかを選べる。
2. **数値入力は上限・下限を超えられる**：スライダーには範囲があり、数値を直接入れたときはもう少し広い範囲まで通す。
3. **複数選択の位置・向きをまとめて変更**：X / Y / Z を軸ごとに比べ、そろっていれば数値を、違っていれば空欄を出し、入力した値に全部をそろえる。

土台は [STACKING.md](STACKING.md)（載っている関係を座標から導く）と [MULTISELECT.md](MULTISELECT.md)（選択は id の配列、操作の対象は「ほかの選択に載っていないもの」）。

---

## 1. 上のものもまとめて削除

### 何が足りなかったか

削除は「選んだものだけを消し、載っていたものは下の面（なければ床）に降ろす」だった。架台の上のラックだけ残したいときはこれでよいが、モジュールを丸ごと片付けたいときは、上のものを先に全部選ぶ必要があった。

### 方針

- **既定は変えない。** `Delete` と削除ボタンのクリックは、いままでどおり上のものを降ろす。うっかり消える量が少ないほうを既定にする。
- **「上のものも一緒に」は、同じ操作に修飾を足した形にする。**

| 操作 | 結果 |
|---|---|
| `Delete` / 削除ボタンをクリック | 選んだものだけ削除。上のものは降りる |
| `Shift+Delete` / 削除ボタンを `Shift`+クリック | 上のものも一緒に削除 |
| 削除ボタンを右クリック | 2 つの消し方を並べたメニューを出す |
| 削除ボタンの横の ▾（上に物が載っているときだけ出る） | 同じメニューを出す |

- メニューには、それぞれ何点が降りるか／消えるかを書く。上に何も載っていなければ、2 つ目は押せない状態で出す（機能があることは伝わる）。
- 消したあとの通知に、一緒に消した数（または降ろした数）を入れる。どちらも `Ctrl+Z` で 1 回で戻る。

### 採らなかった案

- **確認ダイアログを毎回出す**：undo があるので不要。聞かれるたびに手が止まる。
- **設定で既定を切り替える**：その場で選べるほうが早く、設定の場所を覚えなくて済む。
- **右クリックだけ**：気づきにくく、タッチでは出せない。そこで、上に物が載っているときだけ ▾ を出す。
- **切り取り（`Ctrl+X`）で代用**：切り取りは上のものも一緒に持っていくので結果は同じだが、クリップボードを上書きしてしまう。

### 判定の定義

- 「上のもの」は `riders`（直接・間接に載っているもの）のうち、選択に入っていないもの。架台と、その上のラックを両方選んでいれば、ラックは「上のもの」に数えない。
- 上のものを残す場合は、低いものから順に真下の面へ降ろす（既存の `settle`）。架台を消すと、プレートが床に降り、その上のラックはプレートに載ったままになる。
- ロックされたアイテムも消える（いままでの削除と同じ扱い）。

### 実装

```ts
// src/editor/stacking.ts
/** Everything standing on any of `ids` that is not in `ids` itself. */
ridersOf(layout, ids): string[]
/** Remove items; riders drop onto the surface below, or are removed too with `withRiders`. */
removeItems(layout, ids, { withRiders? }): { layout, removed: string[] }
```

| 場所 | 変更 |
|---|---|
| `editor/stacking.ts` | `ridersOf` / `removeItems` |
| `editor/commands.ts` | `itemCommands.remove(ids, { withRiders })`、`itemCommands.riderCount(ids)`、通知の文言 |
| `ui/DeleteButton.tsx`（新規） | クリック・`Shift`+クリック・右クリック・▾ とメニュー。右パネルと、アイテムの上のツールバーの両方で使う |
| `ui/Chrome.tsx` | `Shift+Delete` |
| `ui/styles.css` | `.del-wrap` / `.del-more` / `.del-menu` |

## 2. 数値入力は上限・下限を超えられる

### 何が足りなかったか

パラメータの範囲は「スライダーで動かして破綻しない範囲」として決めてある。そのため、「架台をあと少しだけ長くしたい」「大きなモニターを置きたい」というときに、範囲の端で止まってしまう。

### 方針

- 数値のパラメータに、**スライダーの範囲**（`min` / `max`）と**受け付ける範囲**（`numberLimits()` が返す）の 2 つを持たせる。
  - スライダーは前者で止まる。ふだんはこれで足りる。
  - 数値の直接入力と JSON は、後者まで通す。
- 受け付ける範囲の既定は、**長さ（単位が mm）だけ広げる**。
  - 下限：`min / 4`（`min` が 0 以下ならそのまま）
  - 上限：`max × 4`
  - 個数・角度・比率・インチなどは、スライダーの範囲のまま。
- アセットは、パラメータごとに `hardMin` / `hardMax` で上書きできる（製品寸法に近いものは狭く、自由に伸ばしてよいものは広く）。
- 範囲の外の値が入っているときは、**入力欄を目立たせて「範囲外」と出し**、スライダーのつまみは端に寄せる。スライダーを動かせば範囲内に戻る。
- 入力欄の `↑` / `↓` キーも、受け付ける範囲まで動く。

### なぜ無制限にしないか

- 0 や負の長さは、形が裏返ったり、面の大きさが負になったりする。
- 穴の数や段数は、少し増やしただけでメッシュ数が跳ね上がり、画面が固まる。
- 角度は、関節の可動域など意味のある上限になっていることが多い。

「長さだけ、4 倍まで」は、破綻しにくく、欲しい場面（少し大きい・少し小さい）をほぼ覆う。足りないアセットは個別に広げる。

### 採らなかった案

- **スライダーの範囲そのものを広げる**：つまみの動きが粗くなり、ふだん使う範囲の調整がしにくくなる。ギャラリーの「最小」「最大」も極端な形になる。
- **アセットごとに全部のパラメータへ明示する**：数が多く、書き忘れる。既定を決めて、例外だけ書く。
- **入力時に「範囲を超えますがよいですか」と聞く**：入力した本人はわかっている。見た目で知らせるだけにする。

### 判定の定義

```ts
// src/assets/params.ts
numberLimits(spec): { min: number; max: number }
//   unit === 'mm' → { min: spec.hardMin ?? (spec.min > 0 ? spec.min / 4 : spec.min), max: spec.hardMax ?? spec.max * 4 }
//   それ以外       → { min: spec.hardMin ?? spec.min, max: spec.hardMax ?? spec.max }
```

- JSON の検証（`paramsSchema`）と、描画時の丸め（`resolveParams`）は、受け付ける範囲を使う。
- AI 向けのカタログには、スライダーの範囲を「ふつうに使う範囲」として書き、広げられるものには「〜まで指定可」を添える。AI には、必要なときだけ使うよう RULES に書いてある。
- ギャラリーの「最小」「最大」は、スライダーの範囲のまま（ふだん目にする形を確かめる場所）。

### 壊れないことの確かめ方

`src/__tests__/fields.test.ts` の「every asset still builds at the edge of what can be typed in」が、**全アセットを、受け付ける範囲の最小と最大で組み立てる**。形が有限か、本体の箱と載せられる面がつぶれていないかを見て、だめなアセットを一覧で出す。

- 導入時に見つかったのは 1 件：冷蔵庫を幅 75 mm まで縮めると、庫内の面の幅が負になった。冷蔵庫の幅・奥行き・高さに `hardMin` を付けて直した。
- アセットを足したら、このテストが通るまで `hardMin` / `hardMax` を調整するか、`build` の中で丸める。

### 実装

| 場所 | 変更 |
|---|---|
| `assets/params.ts` | `NumberParam.hardMin` / `hardMax`、`numberLimits()`。検証・丸め・カタログの文言 |
| `ui/controls.tsx` | `NumberSlider` に `hardMin` / `hardMax`。範囲外の表示。スライダーには範囲内に丸めた値を渡す |
| `ui/Inspector.tsx` | `numberLimits()` の結果を `NumberSlider` に渡す |
| `ai/prompt.ts` | RULES に 1 行 |
| `ui/styles.css` | `.num-outside` / `.num-flag` |

## 3. 複数選択の位置・向きをまとめて変更

### 何が足りなかったか

複数を選んだときの右パネルには、そろえる・並べる、と同じ種類のパラメータ編集しかなく、位置と向きは 1 個ずつ直すしかなかった。「同じラックを 5 個並べて、全部を同じ高さに上げる」「向きを全部そろえる」ができなかった。

### 方針

- 右パネルの「位置・向き」を、**1 個でも複数でも同じ部品**にする（`PoseFields`）。
- **軸ごとに独立して比べる。** X / Y / Z それぞれ、全部が同じなら数値を出し、違えば空欄にして「混在」と薄く出す（表計算やスライド作成ソフトの書式欄と同じ）。
- **入力して確定（Enter か、欄の外をクリック）すると、全部がその値になる。** 混在の欄に何も入れなければ、何も変わらない。
- **`+50` と入れると、それぞれを今の位置から 50 mm ずらす。** 戻すときは `-=50`。`-50` は「−50 にする」の意味のまま（マイナスの座標も入れられるように）。全角の数字と記号も読む。
- 欄にフォーカスすると中身を全選択する（打てば置き換わる）。`↑` / `↓` で 1 段（X・Z は 5 mm、Y は 1 mm）、`Shift` で 10 段ずつ、全部を同じだけ動かす。
- **向き**も同じ。全部が同じ向きならそのボタンが選ばれた状態、違えばどれも選ばれていない状態にし、押すと**それぞれがその場で**その向きになる。
  - キーボードの `R`（まとめて回転）は、いままでどおり全体の中心のまわりに回す。パネルのボタンは「向きをそろえる」、`R` は「配置ごと回す」で、役割が違う。
- **種類が混ざっていても使える。** 位置と向きは、どのアイテムにもある。

### 対象の決め方

- 対象は、選んだもののうち「ほかの選択に載っていないもの」（`roots`）で、ロックされていないもの。
- 載っているものは、下のアイテムと一緒に動く（`moveWithRiders`）。架台と、その上のラックを両方選んで Y を変えても、ラックが二重に動くことはない。
- 欄に出す値も、この対象のものだけで比べる。パネルに「ほかの選択に載っているものは、下のアイテムと一緒に動きます」と添える。
- Y を変えたあと、下に面がなければ宙に浮く（いままでの Y 入力と同じ。浮きは JSON の検証で知らせる）。

### 採らなかった案

- **平均値や先頭の値を出す**：そろっているのか違うのかが見分けられない。
- **入力するたびに反映する**：混在の欄では、1 文字目で全部がその値に飛んでしまう。確定してから反映する。1 個のときも同じ動きにそろえた。
- **同じ種類のときだけ出す**：位置は種類によらないので、制限する理由がない。
- **`-50` を「50 減らす」にする**：`+50` と対になって自然だが、マイナスの座標が入れられなくなる。`-=50` を別に用意した。

### 実装

```ts
// src/editor/fields.ts（新規。ストアにもレジストリにも依存しない）
sharedValue(values: number[], tolerance?): number | null      // そろっていればその値、違えば null
parseNumberEntry(text): { value: number; relative: boolean } | null

// src/editor/stacking.ts
setAxis(layout, ids, axis: 0 | 1 | 2, value, relative?): Map<string, Pose>
faceTo(layout, ids, rotation): Map<string, Pose>
```

| 場所 | 変更 |
|---|---|
| `editor/fields.ts`（新規） | そろっているかの判定、入力の読み取り |
| `editor/stacking.ts` | `setAxis` / `faceTo` |
| `editor/commands.ts` | `itemCommands.setAxis(ids, axis, value, relative)`、`itemCommands.faceTo(ids, rotation)` |
| `ui/Inspector.tsx` | `AxisInput` / `PoseFields`。1 個のときの位置欄もこれに置き換え |
| `ui/styles.css` | `.xyz-mixed` |

## この部屋版での扱い

- **受け付ける範囲は「下限はスライダーのまま、上限は 1.5 倍」**（装置版は 1/4〜4 倍）。家具はクッション・シンク・ハンガーの服のように大きさの決まった部品が多く、1/4 まで縮めるとソファ・こたつ・ミニキッチン・ハンガーラックなどの形が崩れた。欲しいのはほぼ「少し大きく」なので、上だけ広げた。`?gallery&limits=min`（または `max`、`&types=` で絞れる）で、全アセットを受け付ける範囲の端で並べて目で確かめられる。
- 削除の通知・メニュー、位置欄の「ばらばら」表示、操作一覧の文言は、部屋版の口調と操作（矢印 10mm、`F` は動線チェック、向きは南・東・北・西）に合わせた。
- 位置欄の `↑` / `↓` は X・Y・Z とも 10mm（`Shift` で 100mm）。キーボードの矢印と同じ刻み。
- 椅子を机の下に入れた関係（`tucks`）は「上のもの」に含めない。机を「上のものも一緒に削除」しても椅子は残る。
- おまけとして、**操作方法とショートカットの画面**（`?` キー、メニューの「操作方法とショートカット」）も入れた。一覧は `src/ui/shortcuts.ts` にあり、操作を変えたらここも直す。
- **壁を 1 面ずつ外す機能は入れていない**。部屋版はカメラの向きに合わせて手前の壁を自動で消す（ドールハウス表示）ので、手で外す必要が薄い。窓のある面を外したときの照明も未検証だった。
- ついでに、3D の中に出るツールバーが右パネルの上に重なって入力欄を隠していたので、`.viewport-wrap` に重なり順の文脈（`z-index: 0`）を持たせて、パネルの下に回るようにした。

## 割り切りと、あとで足せるもの

- 右クリックのメニューは、削除ボタンの上だけ。アイテムそのものを右クリックしたときのメニューはない（右ドラッグがカメラの平行移動なので、取り合いになる）。
- 範囲外の値は、スライダーを触ると範囲内に戻る。「範囲外のまま微調整」は数値入力か `↑` / `↓` で行う。
- 位置の一括変更は、床や面からはみ出しても止めない。重なりは赤枠で知らせる。
- 向きのボタンは 90° 刻みの 4 方向だけ。15° 刻みの向きは「混在」に見える。
- あとで足せるもの：同じ種類のパラメータにも `+50` の相対入力、Y を変えたあとに真下の面へ降ろすボタン、フロアの幅・奥行きの入力にも受け付ける範囲を分ける。
