# 多段の積み重ね（設計メモ）

> 実験自動化装置のレイアウト版（tsubame-layout-designer）で設計・実装し、このリポジトリへ持ち込んだ仕組み。
> 文中の例（架台・プレート・ラック・ロボット）は装置版のまま残してある。部屋版では「デスク → モニター」「本棚の段 → 小物」と読み替えてほしい。
> この部屋版での扱いは「6. この部屋版での扱い」の節にまとめた。

架台の天板 → 穴あきプレート → スタンド → ラック、棚 → 冷蔵庫 → 庫内の棚 → ホルダー、のように、
アイテムを何段でも重ねて置くための仕組み。

実装の中心は [src/editor/stacking.ts](../src/editor/stacking.ts)（アセットにも three.js にも依存しない）。

## 1. もとの仕組みと、足りなかったところ

もとは「床の家具の上に、`placement: 'onTop'` のものを 1 段だけ載せる」作りだった。

| もとの作り | 困るところ |
|---|---|
| 載せられるのは `onTop` のアセットだけ | 載る側と載せる側が種類で固定される。プレートの上のスタンドの上のラック、が表現できない |
| 支える面は「床置き家具の外接箱の上面」だけ | 棚の中段、冷蔵庫の庫内、天板より低い棚板に置けない |
| 高さ 1300 mm を超える家具は面にならない、という決め打ち | 例外をコードに書き足し続けることになる |
| 下の家具を動かしても、上の物はついてこない | 机を動かすたびにモニターを置き直す |
| 当たり判定の「載っている」は 60 mm の許容幅で推定 | 多段になると誤判定が増える |

## 2. 方針

1. **JSON は平らなまま、絶対座標のまま。** 親子関係のフィールドは足さない。
2. **「何が何に載っているか」は座標から導く。** アイテムの原点（底面中心）が、ほかのアイテムの面の矩形の中にあり、高さが面と一致していれば「載っている」。
3. **面はアセットが宣言する。** 何も書かなければ本体の上面が面になる。棚や庫内は段ごとに宣言する。
4. **載っているものは、下のものと一緒に動く。** 移動・回転・複製・削除・寸法変更のすべてで。

### なぜ親子関係を JSON に持たせないのか

`"on": "bench-1"` のような親 ID と相対座標で持つ案も検討した。採らなかった理由は次のとおり。

- **AI と人が読み書きしやすい。** 絶対座標なら「x=1200 の位置にある」と一目でわかる。相対座標だと、親をたどって足し算しないと位置がわからず、親の回転も絡む。
- **壊れ方が穏やか。** 親 ID が間違っている、親が消えている、循環している、といった JSON の不整合が原理的に起きない。高さが少しずれていても「浮いています」と警告するだけで、描画も編集もできる。
- **スキーマを変えずに済む。** 既存のレイアウト JSON がそのまま使える（`version` を上げなくてよい）。
- 引き換えに、「載っている」判定を毎回計算する。アイテム数 n、面の数 m に対して O(n·m) で、数百個の規模なら 1 ms に満たない。

## 3. データ

### 面（`Surface`、[src/assets/types.ts](../src/assets/types.ts)）

アイテムのローカル座標（mm、原点は底面中心、正面 +Z）での水平な矩形。

```ts
interface Surface {
  y: number                 // アイテムの原点からの高さ
  minX: number; maxX: number
  minZ: number; maxZ: number
  clearance?: number        // 上の空き高さ（上に別の棚があるときなど）
  label?: string            // 「天板」「中段の棚」など。AI 向けカタログに出る
}
```

アセット側の宣言：

| 書き方 | 意味 |
|---|---|
| `surfaces` を書かない | 本体（`body`、なければ外接箱）の上面が面になる |
| `surfaces: () => []` | 何も載せられない（ロボット、チューブの刺さったラック） |
| `surfaces: (p) => [...]` | パラメータに応じた面のリスト（天板＋棚板、冷蔵庫の各段＋庫内の床＋天面） |

あわせて、当たり判定のために次の 2 つも宣言できる。

- `body(p)`：当たり判定と吸い付きに使う「本体」の箱。腕や開いた扉が外接箱を広げてしまうアセットで使う。
- `hollow`：中が空いている枠。内側に収まる物とは当たり判定をしない。

### 置かれた面（`PlacedSurface`）

面に、持ち主の位置と向きを足したもの。`worldY = 持ち主の y + surface.y`。
矩形そのものはローカル座標のまま持ち、点が面の上にあるかは「点を持ち主のローカル座標に戻して矩形と比べる」。
こうすると、持ち主が 15° のような半端な角度を向いていても正しく判定できる。

## 4. 判定と操作

`createStacking(host)` に「アイテムの面を返す関数」を渡すと、次の関数群が返る。
アプリ側では `src/editor/placement.ts` の `stack` がそれ（アセットのレジストリとつないである）。

| 関数 | 何をするか |
|---|---|
| `placedSurfaces(layout, except?)` | 部屋の中の面をすべて列挙する |
| `supports(layout)` | 各アイテムが載っている面を求める（床の上・宙に浮いているものは含まれない） |
| `riders(layout, id)` | `id` に載っているものを、孫・ひ孫までたどって返す |
| `restsOn(sup, id, baseId)` | `id` が `baseId` に（間接的にでも）載っているか |
| `surfaceUnder(layout, x, z, { maxY })` | 点の真下でいちばん高い面（なければ床） |
| `pickAlongRay(surfaces, origin, dir, offset)` | マウスの視線が最初に通る面を選ぶ（ドラッグ用） |
| `moveWithRiders(layout, id, to)` | `id` を動かし、載っているものも一緒に平行移動・回転させる |
| `settle(layout, ids)` | 支えを失ったものを、下の面（なければ床）まで落とす |
| `reseat(before, after, id)` | `id` の寸法が変わったあと、載っていたものを新しい面の高さに合わせる |
| `floating(layout)` | 宙に浮いているアイテムを見つける（検証の警告用） |

### 「載っている」の定義

アイテム A が面 S に載っている ⇔

- A の原点 (x, z) が S の矩形の中にあり、
- `|A.y − S.worldY| ≤ 2 mm`（`REST_TOLERANCE`）で、
- S の持ち主が A 自身ではない。

同じ高さに面が 2 つ重なっているとき（天板と、天板と同じ高さのプレートなど）は、面積の小さいほうを選ぶ。

高さは 0.1 mm 単位で丸めて保存する（`roundY`）。整数に丸めると、段を重ねるたびに最大 0.5 mm ずつ隙間ができる。

### ドラッグ：視線が最初に通る面に置く

真上から見たときは「いちばん高い面」でよいが、3D で斜めから見ているときは、それだと棚の中段や冷蔵庫の庫内に置けない。
そこで、マウスの視線（レイ）と各面の平面との交点を求め、**カメラにいちばん近い交点**を選ぶ。

1. ドラッグ開始時に、アイテムが載っている高さの平面と視線の交点を求め、アイテム原点との差（つかみ位置のずれ）を覚える。
2. ドラッグ中は、各面の高さの平面と視線の交点 ＋ ずれ、を「置きたい位置」とする。その位置が面の矩形に入っている面だけが候補。
3. 候補のうち、視線の手前にあるものを選ぶ。候補がなければ床（y = 0）。
4. `clearance` より背の高いアイテムは、その面を候補から外す（棚の中段に入らないものは、入らない）。
5. 面の縁から 25 mm までは、はみ出していても面の上にとどめる（`sticky`）。縁でカクカクと床に落ちるのを防ぐ。

動かしているアイテム自身と、それに載っているものの面は候補から外す（自分の上に自分を置かない）。

候補のうち、次の場所には置かない（`pickAlongRay` の `solids` オプション）。置ける場所がなければ、アイテムは最後に置けた場所にとどまる。

- **ほかのアイテムの本体の中。** 架台の前面を指して、天板の下の床に落ちるのを防ぐ。
- **ほかのアイテムの陰。** 視線が、上に物を載せられるアイテム（架台・デッキ・冷蔵庫など）の本体を先に通る場合。架台を突き抜けて裏の床に置かれるのを防ぐ。ラックやロボットは陰を作らない。自分の面は自分の体に隠されない（庫内の棚、作業台の中段）。

### 吸い付き

- 面の上では、**その面の縁**と、**同じ高さにある隣のアイテムの縁**に吸い付く（しきい値 12 mm）。合うものがなければ 5 mm グリッド。
- 床の上では、もとの挙動（壁・柱・隣のアイテム、しきい値 60 mm、50 mm グリッド）。
- ドラッグ中の寸法ガイドは、部屋の壁までではなく、**いま載っている面の縁まで**の距離を出す。

### 一緒に動かす

| 操作 | 載っているもの |
|---|---|
| 移動（ドラッグ・矢印キー・数値入力） | 同じだけ平行移動する |
| 回転 | 下のアイテムの原点を中心に回り、自分の向きも同じだけ回る |
| 複製 | 載っているものごと複製する。複製先は、その場所の真下の面に載せる |
| 削除 | 載っていたものは、その下の面（なければ床）まで落ちる |
| 寸法の変更 | 面の番号（`surfaces()` の何番目か）を覚えておき、変更後の同じ番号の面の高さに合わせる。面がなくなった・面からはみ出した場合は下に落ちる |

「面の番号で追う」ために、**`surfaces()` が返す順番は、パラメータを変えても意味が変わらないようにする**
（例：0 番はいつも天板、1 番以降が下から順の棚）。

### 当たり判定

2D の外形（`body` の矩形）と高さの範囲が重なっていれば「重なり」。ただし次の 2 つは除く。

- 一方がもう一方に（間接的にでも）載っている。
- 一方が `hollow` で、もう一方の外形がその内側に収まっている。

もとの「`onTop` なら 60 mm の範囲で大目に見る」という推定は不要になった。

### 新しく追加するときの置き場所

`placement: 'onTop'` のアイテムは、追加したときに面を探す。

1. 選択中のアイテムの面を最優先、次に面積の大きい順。高さ 1700 mm までの面が対象。
2. 面の中心から外へ向かって格子状に候補を並べ、ほかのアイテムと重ならない最初の場所に置く。
3. どの面にも空きがなければ、床の上で従来どおり中心から外へ探す。

## 5. 検証と AI 向けの説明

- JSON の読み込み時、宙に浮いているアイテムを警告する（エラーにはしない）。
  例：`items[3].position: 「チューブラック」が宙に浮いています（y=850）。真下の面は y=900 です`
- AI 向けのルール文（`src/ai/prompt.ts`）には、「y は載せる面の高さ」「面の高さは、下のアイテムの y ＋ カタログに書いてある面の高さ」と書く。
- カタログには、各アセットのデフォルト寸法での面の高さを載せる（例：`載せられる面: 天板 y=900 / 棚 y=200`）。

## 6. この部屋版での扱い

- **面の宣言**（`src/assets/items/*.ts` の `surfaces`）
  - 上に物を置かない家具は `surfaces: () => []`：ベッド、敷布団、ソファ、椅子類、ビーズクッション、観葉植物、姿見、ゴミ箱、クッション、テレビ、モニター、フロアランプ、デスクライト、ハンガーラック、縦型洗濯機。
  - **ラグも `[]`**。そうしないと、ラグの上の家具がラグと一緒に動いてしまう。
  - 段ごとに面を返すもの：**本棚**（0 番が天板、続いて下の段から、行ごとに左から）、**カラーボックス**（0 番が天板、続いてインナーボックスのないマス）。`clearance` に段の内寸を入れてあるので、背の高い物は入らない。
  - 見た目と面がずれるものは明示：**こたつ**（布団ではなく天板）、**ミニキッチン**（カウンター。吊り戸棚があれば上の空き 690）、**レンジ台**（天板）、**ドラム式洗濯機**（天面）。
  - それ以外（デスク、テーブル類、チェスト、テレビ台、冷蔵庫）は省略して、本体の上面を面にしている。
- **当たり判定の例外は残した**：`SOFT`（ラグ・カーテン・クッションはぶつからない）と、椅子を机の下に入れてよい `tucks`。`collisions()` の中で「載っている」「中空の枠」と並べて判定している。
- **新しく置くときの優先**：選択中の家具 → `PREFERRED_SUPPORT`（モニターはデスク、テレビはテレビ台…）→ 広い面の順。
- **スナップ**：床の上は従来どおり（しきい値 80 mm・グリッド 50 mm）、面の上はしきい値 30 mm・グリッド 10 mm。
- **動線チェック**：何かに載っているもの（テレビ台の上のテレビなど）は、下の家具が場所をとるので障害物から外した。
- 壁付け・天井付けは積み重ねの対象外で、ドラッグも従来の処理のまま。

## 7. いまの割り切り

- **面は水平な長方形だけ。** 丸い天板や L 字の天板は、外接する長方形で近似するか、長方形を複数宣言する。
- **載っているかは原点（底面中心）の 1 点で決める。** 縁からはみ出して置くことはできる（重心が外れても落ちない）。
- **面にくぼみや穴があっても考慮しない。** スタンドの窓にラックを落とし込むような「はめ込み」は、高さを手で合わせる。
- **傾いた面、壁面への取り付けは対象外。** 壁掛けは従来の `placement: 'wall'` のまま。
- **同じ高さの面が重なるときは、小さいほうに載る**という決めだけで、明示的な指定はできない。
